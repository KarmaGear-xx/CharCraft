# CharCraft 项目维护文档

> 用途:后续维护 / 续作时的完整上下文参考。记录需求、功能、实现方式、构建流程与环境注意事项。
> 生成时间:M4 完成时。

---

## 1. 项目概述

**CharCraft** —— 类 Ginger 的 **SillyTavern 角色卡开发/编辑工具**,以 **Windows 便携版单文件 `.exe`** 交付(免安装、双击即用)。

- 框架:Electron(单一 TypeScript 语言、打包链路成熟、维护成本低)
- 功能定位:导入 / 生成 / 编辑角色卡,绑定世界书,导出 `.json` / `.png`
- 关键约束:卡片数据字段名与内容恒为英文;UI 中英双语仅影响显示层

## 2. 交付物与产物

## 4. 架构(Electron 三层)

```
src/
  main/     主进程(Node.js):窗口、原生对话框、文件读写、AI 直连、配置/草稿存取
  preload/  contextBridge 安全桥,暴露 window.api
  renderer/ 渲染进程(React):界面 + 核心逻辑 + 状态
  shared/   跨进程共享类型与 IPC 契约
```

- 渲染进程 **不直接接触 Node/文件系统**,全部通过 `window.api`(preload + IPC)。
- 主进程 `webPreferences`: `contextIsolation: true`、`nodeIntegration: false`、**`sandbox: false`**(关键:沙箱化预加载无法 require 相对模块,曾导致白屏)。

### IPC 契约(`src/shared/ipc.ts` → `window.api`)

| 方法 | 用途 |
|---|---|
| `openCard()` | 原生打开对话框(.png/.json/.charx) |
| `openFile(filters)` | 通用打开对话框(头像、世界书导入) |
| `saveFile(name, filters, bytes)` | 原生另存为 |
| `aiChat(settings, messages, opts)` | AI 调用(**主进程直连,无 CORS**) |
| `getConfig() / setConfig()` | 应用设置 |
| `getDraft() / setDraft()` | 草稿(含快照) |

## 6. 数据模型与文件格式

### 6.1 角色卡格式(均支持导入,`.charx` 仅导入)

| 格式 | 内嵌方式 |
|---|---|
| `chara_card_v2`(spec 2.0) | PNG `tEXt` 块,键名 `chara`,值 = base64 JSON |
| `chara_card_v3`(spec 3.0) | PNG `tEXt` 块,键名 `ccv3`,值 = base64 JSON;含顶层字段镜像 + `data` |
| `.charx` | ZIP 压缩包,内含 `card.json` + 可选资源文件(图片等) |
| 独立世界书 | JSON,`entries` 为**对象**(键为索引)或数组两种形式 |

### 6.2 标准字段(`data` 对象)

核心区:name / description / personality / scenario / first_mes / mes_example / alternate_greetings / system_prompt / creator_notes / tags / creator
高级区(默认禁用):post_history_instructions / character_version / group_only_greetings
其余:avatar、character_book、extensions、group_only_greetings

### 6.3 扩展字段(`data.extensions`)

- `chub`(Chub 数据)、`depth_prompt`({depth,prompt,role})、`fav`、`talkativeness`、`world`
- **未知扩展一律原样保留**(导入导出不丢)

### 6.4 应用本地存储(`%APPDATA%\CharCraft\`)

| 文件 | 内容 |
|---|---|
| `config.json` | lang / theme / aiSettings / snippets / customRecipes / tokenBudget |
| `draft.json` | card / enabled / image(头像 rgba 以 base64 存) / subFields / snapshots / sourceName |

## 7. 功能清单(按里程碑)

**M1 基础闭环**:导入 .png/.json → 表单编辑(字段启用/禁用 + AI 改写 + 高级折叠)→ AI 整卡/逐字段生成(覆盖保护 4 策略 + 费用提醒)→ 世界书生成绑定 → 导出 .json/.png → 双语 → 草稿自动保存。

**M2 进阶**:对话/开场白格式化(4 风格);头像裁剪/缩放;世界书导入/导出/合并;`.charx` 导入。

**M2.5 补强**:新建卡片可选图片作头像;描述子项(全名/性别/年龄/特点/性格/喜欢/不喜欢/身材)导出时合并进 description 开头。

**M3 效率工具**:Recipes 配方(12 内置 + 自定义,AI 生成烘焙);Snippets 片段(增删 + 插入字段);跨字段查找替换;Token 计数与预算(每字段 + 总计/预算,预算可配)。

**M4 收尾**:性别转换/代词替换(大小写感知、跨字段);多平台扩展编辑(depth_prompt/talkativeness/fav);深色模式;增量保存(快照/版本历史)。

## 8. 关键实现细节

- **PNG 编解码**:手写 chunk 解析 + 浏览器原生 `CompressionStream`/`DecompressionStream`(zlib),零原生依赖。
- **AI 调用**:由主进程 `fetch` 直连 OpenAI 兼容接口(`baseUrl + '/chat/completions'`),渲染进程经 `aiChat` IPC 调用,规避 CORS。预设 OpenRouter / DeepSeek / 自定义。
- **费用提醒**:每次启动后首次 AI 生成弹窗(内存标志,重启重置)。
- **覆盖保护**:整卡生成前若已有内容,弹 4 选项(取消 / 清空覆盖 / 仅填空 / 手动选目标)。
- **描述子项合并**:`mergeDescription()` 在**导出时**把非空子项以 `英文标签: 值` 每行一条拼到 description 前(标签英文,遵循英文内容约束)。
- **性别转换**:`gender.ts` 单词级双向替换,映射 `his→her`、`her→him`、`hers→his`;大小写三态保留(见局限)。
- **深色模式**:`data-theme` 属性 + CSS 变量(`--bg/--panel/--field-bg/--input-bg/...`),主题随 config 持久化。
- **快照**:`draft.json` 内 `snapshots[]`(card/enabled/subFields/timestamp),不含头像图像;恢复时保留当前头像。
- **字段 token 计数**:字段头显示;总计走 `countCardTokens()`(gpt-tokenizer)。
- **默认启用策略**:核心字段默认启用;高级字段默认禁用,**导入卡若高级字段已有内容则自动保持启用**(避免导出丢数据)。

## 10. 环境与沙箱注意事项(重要!)

本机(DSH 沙箱)下的特殊处理,迁移到常规环境可忽略:

1. **TypeScript 7(原生编译器)**:已移除 `moduleResolution: node10`;主进程 tsconfig 用 `module: node16` + `moduleResolution: node16`。
2. **pnpm 11**:`package.json` 的 `pnpm` 字段已不生效;`.npmrc` 中设 `verify-deps-before-run=false`(避免运行脚本前依赖自检在沙箱崩);`electron-winstaller` 的「ignored builds」警告可忽略(便携版不需要)。
3. **沙箱 EPERM**:vite/rolldown/vitest/electron-builder 内部会 spawn 子进程(命名管道),当前沙箱禁止 → 需以 `danger-full-access` 权限执行这些命令。
4. **Electron 二进制下载**:
   - 正确缓存环境变量是 `electron_config_cache`(小写下划线),不是 `ELECTRON_CACHE`;
   - GitHub 直连慢/被限,用镜像 `ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/`;
   - electron-builder 另需 `ELECTRON_BUILDER_CACHE` 与 `ELECTRON_BUILDER_BINARIES_MIRROR=https://npmmirror.com/mirrors/electron-builder-binaries/`。
5. **pnpm 存储**:`.npmrc` 把 store/cache/state 指向工作区(`.pnpm-store` 等),避免写用户目录被沙箱拦。

## 11. 已知局限与后续建议

1. 未设**自定义图标**(默认 Electron 图标);未**代码签名**(首次运行 SmartScreen 会提示)。
2. `.charx` 仅支持**导入**,未实现导出;且 ZIP 内头像仅解码 **PNG**(jpg/webp/gif 未接)。
3. 性别转换的英语 **`her` 一词歧义**(宾语 vs 物主限定),单词级替换无法完全区分;`her book` 类可能转错,需人工微调。
4. AI 生成链路依赖真实 API key,**未做端到端实测**(逻辑已被单测覆盖)。
5. renderer 打包体积因 gpt-tokenizer 词典约 2.3 MB(可接受)。
6. 后续可加:Recipes/Snippets 的导入导出与分享、多图片格式头像、代词上下文精判、`.charx` 导出、增量保存的自动版本。
